GLOSSARY
Eight ideas, in a few lines each

          
★ Local vs. cloud AI
A cloud service such as ChatGPT runs its model on someone else's computers, and your words travel there and back. A local model runs on your own laptop, so your words stay here and it works without internet once it's set up. The trade-off: your laptop's memory limits how big a model you can run, so local models are usually smaller and make more mistakes.

          
★ How a reply gets generated
Your message is split into tokens, and each token becomes numbers. The model uses its learned parameters to work out which token is likely to come next, adds it, and repeats. That loop is why replies appear piece by piece, and why memory and processor speed set the pace. It's prediction, not looking up facts, which is why answers can sound confident and still be wrong.

          
01 Model & runtime
The model is a file of learned numbers. It can't do anything by itself. Ollama is the engine that loads that file and turns your question into a reply, so you need both: the engine, and a model for it to run.

          
02 Parameters & quantization
“1.5B” means the model has about 1.5 billion learned numbers. More numbers usually means better answers, but also more memory. Quantization, the “Q4_K_M” you'll see in model names, stores each number more roughly so the file is smaller and fits in less memory, at a small cost in quality.

          
03 Tokens & context
A token is a piece of a word, so “understanding” might be two or three tokens. The context is everything the model is holding in mind right now: your message plus the reply so far. A longer context needs more memory and takes longer to get going.

          
04 First response & generation speed
Two different waits. The first is the pause before anything appears, while the model reads your whole message. The second is how fast the words then flow, measured in tokens per second. A model can start slowly and still type quickly once it gets going.

          
05 CPU, GPU & memory
The model has to fit in memory before it can run at all, so free memory decides what you can use. Then the processor does the work. If your laptop has a graphics chip, Ollama may use it, which is why the CPU can look idle while replies come fast.

          
06 Repeats & fair comparisons
The first reply after loading is slower, so we run a warm-up and skip it. Then we ask the same questions three times and look at the middle result. Comparing two laptops only makes sense with the same model, the same settings and the same questions, and with other apps closed.

HOW TO MEASURE FAIRLY

    Set the conditions
    Plug in your laptop, close big apps, and keep the same model and settings between runs.
  2. 02
    Warm up, then repeat
    The first reply after loading is slower, so the lab runs one warm-up and skips it. Then it asks a short, a medium and a long question three times each.

    Save the results
    Start the Lab Helper and approve Measure on this page. It saves a results file on your laptop. Anything it couldn't measure stays blank, because a failed measurement is not a zero.
  4. 04
    Read them
    The Lab Helper shows them under Results right away. You can also open the file under Results on this public site, which never connects to your laptop.

CPU is one piece of the picture.
The CPU number is how busy your processor was, out of 100. A low number with fast replies usually means a graphics chip did the heavy lifting. We don't measure the graphics chip, so a low CPU number is not a problem.
Memory has a boundary.
The memory number is how much the model was using while it ran. It is not the size of the file you downloaded, not the least it could get by with, and not what your whole laptop was using. Treat it as a good estimate, not an exact figure.
A middle result is not a verdict.
Only compare runs that used the same model, settings and questions. Heat, battery mode and what else was open all change the numbers. And a faster reply says nothing about whether the answer was any good.
