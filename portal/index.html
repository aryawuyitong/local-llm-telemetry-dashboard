BEFORE YOU BEGIN

Six ideas worth knowing

01 Model & runtime

A model is a set of learned parameters. A runtime, such as Ollama, loads those weights and generates output. A download alone is not a running service.

02 Parameters & quantization

“1.5B” means about 1.5 billion parameters. Quantization stores weights using fewer bits. It can reduce memory and disk needs, with a possible quality trade-off. File size alone does not predict total runtime memory.

03 Tokens & context

Tokens are chunks of text, not always words. Context includes the input and the tokens being generated. More context can require more memory and prompt-processing time.

04 First response & generation speed

Our TTFT proxy is the client-observed wait from request start to the first non-empty response text, not a verified token boundary. TPS describes output generation after prompt processing. A model can start slowly yet produce tokens quickly afterward.

05 CPU, GPU & memory

CPU measures processor activity. A GPU may do much of the inference, so low CPU does not imply a broken model. Our RSS measurement excludes separate GPU memory and is not total system memory.

06 Repeats & fair comparisons

A warm-up separates loading from steady-state runs. Repeat the same prompts with the same model, settings, and context. Background applications, heat, caching, and power mode can all change the results.

CPU is one piece of the picture.
CPU is normalized by logical core count. Low CPU with fast generation can indicate GPU offload. This lab does not measure GPU utilization.
Memory has a boundary.
RSS is sampled process memory, not model file size, a theoretical minimum, total system use, or dedicated GPU memory. Shared pages can be counted twice across processes.
A median is not a verdict.
Compare matching settings, prompt, model digest, and runtime. Timing, caching, thermal state, and power mode can vary. A faster response says nothing by itself about answer quality.
